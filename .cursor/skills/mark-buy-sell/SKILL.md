# 缠论买卖点标记

通过 CDP 连接 TradingView Desktop，基于**各周期上画的笔**，按照缠论定义在图上标记各周期的 **1、2、3 类买卖点**（红色文字，跨周期共振点用绿色文字）。

> **模块分类**：基础公用组件（所有交易策略共用的结构计算；分层见 `.cursor/skills/README.md`）。
>
> **算法来源**：所有缠论算法（含买卖点识别）由 **`chan-core`**（`.cursor/skills/chan-core/scripts/chan_core.js`）提供（唯一算法源），本脚本只负责读取笔数据、调算法、绘制标记。修改算法规则请改 `chan-core`。
>
> **强制依赖画笔数据**：本 SKILL **不再自己计算笔**，而是**强制读取 `chan-bi` 画笔 SKILL 落盘的笔数据文件**（`.cursor/cache/bis_<品种>.json`）。如果文件不存在、或文件品种与当前图表品种不一致，脚本会**报错退出**，必须先对当前品种运行「画笔」后再标记买卖点。

## 前置条件

1. TradingView Desktop 以调试模式启动：`TradingView.exe --remote-debugging-port=9222`
2. 已打开至少一张图表，且图表停留在**要标记的品种**上（脚本自动读取当前品种和周期）
3. chrome-remote-interface 已安装（在 `server-cdp/node_modules/`）
4. **已对该品种运行过「画笔」**（chan-bi SKILL），生成了 `.cursor/cache/bis_<品种>.json` 笔数据文件

## 使用方式

```bash
# 在图表上标记各周期买卖点（必须指定起始日期，默认标记 日线/4小时/1小时/15分钟/3分钟 五个周期）
node .cursor/skills/mark-buy-sell/scripts/mark_buy_sell.js --from=2026-07-02

# 只计算并打印买卖点，不绘图（先验证再标）
node .cursor/skills/mark-buy-sell/scripts/mark_buy_sell.js --dry --from=2026-07-02

# 只标记指定周期（例如只标 1小时 和 4小时）
node .cursor/skills/mark-buy-sell/scripts/mark_buy_sell.js --from=2026-07-02 --periods=240,60
```

> `--from` 起始日期应与画笔时一致（脚本会读取该日期之后的笔数据来计算买卖点）。
> 小周期K线加载窗口与画笔同源：参数中心「基础组件 → 画笔」的「小周期绘制窗口」（`windowDays3/15/30S`），
> 手动调用时若参数中心有自定义值应加 `--chan-cfg=` 透传（导出方式见 chan-bi SKILL）。

### 参数说明

| 参数 | 说明 | 默认值 |
|------|------|--------|
| `--from=YYYY-MM-DD` | **必填**：起始日期，所有周期都从该日期开始计算笔和买卖点 | 无（缺少时报错退出） |
| `--periods=...` | 要标记的周期列表（逗号分隔，从大到小） | `D,240,60,15,3` |
| `--keep=N` | 每周期保留的标记总数（不分类：买+卖合并后只保留时间上最近的 N 个） | `10` |
| `--dry` | 只计算不绘图 | 关闭 |
| `--debug` | 打印一类落点/跳过过程、标记列表等调试信息 | 关闭 |

## 起始日期规则（每次标记必做，且必须输入日期）

**用户说「标记买卖点」时，必须先询问「起始日期」（格式 `YYYY-MM-DD`，如 `2026-07-02`），得到日期后再执行标记。不得在未获得日期的情况下直接运行脚本。**

```
① 询问：本次标记买卖点从哪个日期开始？（格式 YYYY-MM-DD，如 2026-07-02）
② 用户给出日期 → 运行 node mark_buy_sell.js --from=YYYY-MM-DD
③ 用户未给出明确日期 → 再次询问，直到获得日期后才执行
```

## 标记规则

### 标记前先清除旧标记

每次标记买卖点前，会先**清除已经存在的买卖点标记**：
- 脚本开始会依次切到各周期，删除所有标签为 `CHAN_BUYSELL_<周期>` 的图形
- 然后重新计算并在各周期绘制最新的买卖点

### 基于各周期的笔（强制读盘）

买卖点基于**各周期自己画的笔**计算：脚本读取 `chan-bi` 画笔 SKILL 落盘的
`.cursor/cache/bis_<品种>.json` 笔数据文件（该文件包含各周期已完成 ATR过滤、未完成笔延伸、
跨周期端点校准的最终笔，与图上所画笔完全一致），然后调用 `chan-core` 的买卖点算法计算并标记。

- 找不到笔数据文件 / 品种不匹配 → **报错退出**，提示先运行「画笔」；
- 某周期在笔数据文件中没有笔（画笔未覆盖该周期）→ 跳过该周期并提示；
- 仍会读取当前周期K线，仅用于：买卖点文字偏移量（ATR）、标记吸附到本周期bar边界、MACD 背驰判定。

### 买卖点定义（缠论）

| 类型 | 定义 |
|------|------|
| 一买 | 有上一级别时：上一级别**已确认上涨笔的起点**，或**已确认下跌笔的终点**。与该上级笔**同笔**（起终点时间、价格重合）的端点不标。没有上一级别（日线）时，仍是本级下跌笔**创新低**即标记（`firstNoDiverge`，背驰不是硬门槛） |
| 二买 | **每个 1买 各自锚定**（2026-10-14：窗口=锚到下一个 1买，后续新锚不清前序列）：锚后首个抬高低点（高于锚价）；**不依赖中枢** |
| 类2买 | 同锚序列内其后每个仍高于锚价的抬低（不要求高于上一点）；端点破锚价 → 该锚序列作废（含已发射点） |
| 三买 | 离中枢（破 zg）后回踩不回枢（`price > zg - thirdZsTol`）；同段第1个；**无中枢不标** |
| 类3买 | 同段第2个离枢回踩；与三买同结构 |
| 4买 | 同段第3个离枢回踩；与三买同结构 |
| 类4买 | 同段第4个及以后的离枢回踩；与三买同结构 |
| 一卖 | 有上一级别时：上一级别**已确认上涨笔的终点**，或**已确认下跌笔的起点**。同笔端点不标。没有上一级别时，仍是本级上涨笔**创新高**即标记 |
| 二卖 | **每个 1卖 各自锚定**（2026-10-14：窗口=锚到下一个 1卖，后续新锚不清前序列——已收盘上级下跌笔内的 2卖 是既成结构）：锚后首个次高点（低于锚价）；**不依赖中枢** |
| 类2卖 | 同锚序列内其后每个严格更低的次高；介于前一点与锚价之间不标、序列等待；端点破锚价 → 该锚序列作废 |
| 三卖 | 跌破 zd 后反弹不回枢（`price < zd + thirdZsTol`）；同段第1个；**无中枢不标** |
| 类3卖 | 同段第2个离枢反弹；与三卖同结构 |
| 4卖 | 同段第3个离枢反弹；与三卖同结构 |
| 类4卖 | 同段第4个及以后的离枢反弹；与三卖同结构 |

**MACD 背驰判定**（二类弱档闸，以及没有上级时的可选对照；有上级的一类端点不看背驰）：
- 比较**当前笔**与其前一个**参照笔**（向前找最近的有效同向笔，跳过幅度不足当前笔 50% 的次级别回调）的 MACD 动能指标；
- 背驰 = 满足以下**任一**（OR）：
  1. **MACD 柱状体面积变小**：
     - 底背驰（一买）：下跌笔区间内绿柱面积（macd<0 柱绝对值累加）小于参照下跌笔；
     - 顶背驰（一卖）：上涨笔区间内红柱面积（macd>0 柱累加）小于参照上涨笔；
  2. **黄白线高度动能减弱**：
     - 底背驰（一买）：区间内 DIF 最低点**抬高**（高于参照笔的 DIF 低点）；
     - 顶背驰（一卖）：区间内 DIF 最高点**变低**（低于参照笔的 DIF 高点）；
  3. **柱状体最大高度变小**：
     - 底背驰（一买）：绿柱最大高度（单根柱绝对值最大值）小于参照下跌笔；
     - 顶背驰（一卖）：红柱最大高度（单根柱最大值）小于参照上涨笔。
- 有上一级别时，一类只看上级已确认笔端点，不要求本级背驰。没有上级时，创新低/创新高即标记（`firstNoDiverge`）。二类族按已收笔上级笔方向开窗（上涨笔内只标买点、下跌笔内只标卖点）；背驰闸开且窗口起点前上级同向笔无背驰时，二类里的弱档点不标。

**区间套原则（重要）**：
- 买卖点标记**必须以第一步画笔的结果（日线笔）为总框架**，逐级区间套；
- **2买/类2买**、**2卖/类2卖** 按「已收笔上级笔方向开窗」发射（2026-10-14）：买侧窗口=已收笔上级上涨笔跨度、卖侧=下跌笔跨度，窗口内首个回踩/反抽 = 2买/2卖、其后每个 = 类2买/类2卖；窗口内点是既成结构，**不因后续走势作废**——例：1小时 2卖@10-7 03:00(4184.385) 在 4小时已收盘下跌笔内，4小时新上涨笔确认后仍保留；
- **4小时（主要操作级别）保留区间套下的全部结构段标记**：例如 **7-11 的 75.22**（日线第一段上涨笔内）与 **8-13 的 85.85**（日线第三段上涨笔内）都标记 2买；
- **全部周期（日线/4小时/1小时/15分钟/3分钟）先保留**各周期区间套下识别出的全部买卖点——包括 **全部 1买/1卖**（每个 MACD 背驰底/顶都标记，如 1小时 7-11(75.22) 与 7-29(80.67) 两个 1买 都保留）；多个候选锚定到同一上级位置时只保留一个（去重）；最后**每周期不分类只保留时间上最近 10 个**标记（`--keep=N` 可调，买+卖合并计数）。

**买点示例（4小时）**：日线笔 上涨(70.14→102)→下跌(102→78.11)→上涨(78.11→94.83)；4小时 2买 在日线第一段上涨笔内的 7-11(75.22) 与第三段上涨笔内的 8-13(85.85)，而日线下跌笔内部（如 80.67）不标买点。

**三买示例（1小时）**：2买 = 8-14 21:00(86.53)；2买 过后上涨笔 #45 涨至 8-20 20:00(94.71)，突破 2买 之前的前顶（88.69，即 2买 之前最近上涨笔的结束点），无背驰；其后回调笔 8-20 20:00 → 8-21 17:00(92.74) 不破前顶、且位于 4小时 上涨笔(8-13 22:00→8-22 00:00) 内部 → **3买 = 8-21 17:00(92.74)**。类似地，2买 = 8-7 20:00(81.50) 过后上涨笔 #39 涨至 8-11 16:00(90.03)，突破前顶 84.44，其后回调笔 8-11 16:00 → 8-11 21:00(86.60) 不破前顶、位于 4小时 上涨笔(8-5 08:00→8-12 12:00) 内部 → **3买 = 8-11 21:00(86.60)**。同一位置若同时满足类2买，优先标记为 3买。

**卖点示例（4小时）**：日线下跌笔(102→78.11) 段内，2卖 = 8-1(91.36)，类2卖 = 8-4(86.33)；1卖 = 最近背驰顶 8-22(94.83)。

**1买/1卖**（2026-10-13）：有上一级别时，一类点 = **大级别上涨笔内部的小级别起点**（=1买）/**内部的小级别终点**（=1卖）；下跌笔对称（起点=1卖、终点=1买）。不再先算本级候选再锚定，也不再二次锚定回上级端点。上级端点时刻是上级 K 开盘，真实极值在小级别上——落点用 `lowerVertexOf` 阶梯：±1根本级K同价（最近）→ 上级一根K覆盖窗同价（最晚）→ 笔跨度内同价（最近）→ 跨度内同角色极值（底=最低/顶=最高）；仅跨度内没有同角色小级别顶点（该笔内小级别无结构）才保持大级别时刻。日线没有上级，仍走本级创新低/创新高。

**二买/二卖族按已收笔上级笔方向开窗**（2026-10-14）：取消 1买/1卖 锚定序列与破锚价作废。买侧窗口 = 已收笔上级上涨笔跨度 (startTime, endTime]（卖侧=下跌笔），窗口内小级别只标本侧点——首个回踩/反抽端点 = 2买/2卖，其后每个 = 类2买/类2卖（卖侧放宽为镜像，不再要求严格更低压低）；既成结构，窗口内点不因后续走势作废。背驰闸（secondDivergeGate 仅拦弱档）按各窗口起点取值一次（窗口起点时刻上级末两根确认同向笔 isBiDiverge，上级自身 MACD 优先/缺省区间套兜底），被闸点仍推进序列不重编号；强弱 strong 不变。无上级（日线）与未成笔尾段局部序列走旧锚定口径（锚/破锚价作废/卖侧严格压低）。

### 一类端点（跨周期）

| 周期 | 一类来源 |
|------|------|
| 日线 | 无上级，本级创新低 = 1买，创新高 = 1卖 |
| 4小时 | 日线已确认笔端点 → 落到 4小时级别顶点 |
| 1小时 | 4小时已确认笔端点 → 落到 1小时级别顶点 |
| 15分钟 | 1小时已确认笔端点 → 落到 15分钟级别顶点 |
| 3分钟 | 15分钟已确认笔端点 → 落到 3分钟级别顶点 |

够笔的形成段按已确认笔处理。相邻两笔共用的端点，只要其中一笔是同笔，这个端点就不标。

### 同笔不标

本周期某笔与上一级别某笔起终点的时间和价格都重合（`isSameAsUpperBi`，时间容差 = 本周期 1 根 K 线，价格容差 0.01），该上级笔的两个端点在本级别都不标 1买/1卖。时间容差取一个本周期 bar，是因为低级别端点落在更小周期边界、上级端点落在本周期边界，同一笔两端最多差一根本周期 K 线。

例：15分钟 8-14 16:12→21:39 与 1小时 8-14 16:00→21:30 同笔，15分钟不标这段的 1买/1卖。

### 大级别未成笔的尾段

上一级别最后一根已确认笔结束之后、到覆盖末端、还没走出新笔的那几根 K 线（未够笔的形成段也算），里面的小级别**多空买卖点都要标**。尾段里的一类用本级创新低/创新高追加，不替换前面已经按上级端点算出的一类，因此历史二买序列保持不动；尾段二类只留尾段内的点；尾段三类只看尾段自己的中枢，无中枢仍不标三类。

### 动态更新

大级别有几笔发生变化时，从发生变化的最大周期开始，该周期和全部更小周期的买卖点整表重算；没变的更大周期沿用上次标记。图表侧把笔端点指纹存在 `.cursor/cache/buysell_<品种>.json`（逻辑版本 `20261014-second-per-anchor`），下次只清除并重画变脏的周期。

## 显示规则

- **每周期最多显示最近 10 个标记**：买点+卖点合并按时间排序，每周期只保留时间上最近的 `--keep`（默认 10）个，不保证每类都有；
- 买卖点用**红色文字**标记（文本标签，如 `1买` `2买` `3买` `1卖` `2卖` `3卖`）；
- **跨周期共振标记改绿色**：本级别的 `1买`/`1卖` 若与**紧邻上一级别**的 1/2/3 类买卖点（含类2/类3买/卖）落在**同一点位**（原始时间/价格一致，时间差 ≤ 60 秒、价格差 ≤ max(ATR×0.2, 0.05)），说明该 1 类点同时是上级买卖点，则该标记颜色改为**绿色**，其余保持红色。例：4小时 `2买@7-11 05:00(75.22)` 同时是 1小时 `1买@7-11 05:00(75.22)`，故 1小时的 1买 用绿色显示；15分钟 `1买@8-21 17:00` 同时是 1小时 `3买@8-21 17:00`，故 15分钟的 1买 用绿色显示；
- **只在该周期显示**：每个周期的买卖点通过 `intervalsVisibilities` 设置为只显示本周期（例如 4小时的买卖点只在 4小时 图可见，切到 1小时 自动隐藏），不会跨周期显示；
- 买点文字画在极值价格**下方**，卖点文字画在极值价格**上方**（偏移量按 ATR 自适应）；
- 标记不锁定，可自行编辑/拖动。

## 常见问题排查

| 问题 | 可能原因 | 检查命令 |
|------|----------|----------|
| ECONNREFUSED | TradingView 未以调试模式启动 | `netstat -ano \| findstr 9222` |
| 未找到页面 | 图表标签未打开 | 打开一张图表即可 |
| 提示缺少 --from | 未输入起始日期 | 必须询问用户起始日期后执行 |
| **报错「未找到 XX 的笔数据文件」** | 未先运行「画笔」SKILL（chan-bi），或缓存被清空 | 先对当前品种运行画笔（会生成 `.cursor/cache/bis_<品种>.json`），再运行本脚本 |
| **报错「笔数据文件属于 XX，与当前品种不一致」** | 缓存文件是其他品种画笔时生成的 | 先对当前品种运行画笔，再运行本脚本 |
| 某周期跳过（笔数据为空） | 画笔未覆盖该周期（如 `--periods` 未包含） | 用画笔 SKILL 重新画该周期 |
| 某周期没有一买标记 | 该笔与上级笔完全重合（同笔，由上级标记），或上级最近端点不是上涨笔起点/下跌笔终点（当前段无对应一类端点），或该笔跨度内小级别无任何顶点（无结构，保持上级时刻） | `--debug` 查看 `[一类跳过-同笔]` 与落点过程 |
| 一卖标在上涨途中（如 15分钟 8-17 10:00） | 该局部顶位于上级上涨笔内部、上涨仍在延续，一类点应已随上级上涨笔终点落在笔内部最高小级别顶点 | 切换上级周期核对上涨笔结束点 |
| 某周期一卖/一买未标 | 该端点属于与上级完全重合的同笔，同笔两端都不标；或该端点不是上级已确认笔的端点 | 对照上级笔起终点与 `isSameAsUpperBi` |
| 三买未标出 | 三买对每一笔二买后寻找（每段最多一个），需存在「突破前顶的上涨笔 + 其后第一个回调不破前顶」的组合，且回调须位于上级上涨笔内并高于该笔起点价；若回调跌破前顶、二买之后无创新高上涨段、或回调恰落在上级笔起点（新段启动点）则不标 | `--debug` 查看二买及前后笔结构 |
| 清除后旧标记还在 | 旧标记周期未在当前运行列表里 | 默认标记 D,240,60,15,3 全部周期 |

## 注意事项

- 脚本自动读取**当前图表**的品种和周期，切换品种后需重新运行。
- **必须先对该品种运行「画笔」**（chan-bi SKILL）生成笔数据文件，本脚本才能标记；否则报错退出。
- 本 SKILL 只负责买卖点标记，**不画笔、不清除笔**（画笔用 `chan-bi` SKILL）。
- 标记前会清除所有周期的旧买卖点（`CHAN_BUYSELL_*`），旧笔（`CHAN_BI_*`）不受影响。


## 预期笔与够笔运行笔（2026-09-17 更新）

下跌够笔且普通底分型右肩收盘后，预期上涨段立即参与下级买卖点、中枢归属和方向判断；卖侧镜像。合并后从起点块起满5块（含起点）才通过够笔门槛；进场预期够笔同样使用合并K线。活动端点不锚定已确认一类点，原始画笔缓存与结构视图分开。Python与JS共用同构 `buildStructureContext` / `mergedSegmentCount` 规则，详见 [统一规范](../../../../spec/plans/SPEC_structure_context.md)。
