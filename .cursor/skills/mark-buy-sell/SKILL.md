# 缠论买卖点标记

通过 CDP 连接 TradingView Desktop，基于**各周期上画的笔**，按照缠论定义在图上标记各周期的 **1、2、3 类买卖点**（红色文字；2026-10-14 规则v3 起跨周期共振变绿与真1买/真1卖 合并已删除，全部红色）。

> **模块分类**：基础公用组件（所有交易策略共用的结构计算；分层见 `.cursor/skills/README.md`）。
>
> **算法来源**：所有缠论算法（含买卖点识别）由 **`chan-core`**（`.cursor/skills/chan-core/scripts/chan_core.js`）提供（唯一算法源），本脚本只负责读取笔数据、调算法、绘制标记。修改算法规则请改 `chan-core`。
>
> **强制依赖画笔数据**：本 SKILL **不再自己计算笔**，而是**强制读取 `chan-bi` 画笔 SKILL 落盘的笔数据文件**（`.cursor/cache/bis_<品种>.json`）。如果文件不存在、或文件品种与当前图表品种不一致，脚本会**报错退出**，必须先对当前品种运行「画笔」后再标记买卖点。

## 前置条件

1. TradingView Desktop 以调试模式启动：`TradingView.exe --remote-debugging-port=9222`
2. 已打开至少一张图表，且图表停留在**要标记的品种**上（脚本自动读取当前品种和周期）
3. chrome-remote-interface 已安装（在 `server-cdp/node_modules/`）
4. **已对该品种运行过「画笔」**（chan-bi SKILL），生成了 `.cursor/cache/bis_<品种>.json` 笔数据文件

## 使用方式

```bash
# 在图表上标记各周期买卖点（必须指定起始日期，默认标记 日线/4小时/1小时/15分钟/3分钟 五个周期）
node .cursor/skills/mark-buy-sell/scripts/mark_buy_sell.js --from=2026-07-02

# 只计算并打印买卖点，不绘图（先验证再标）
node .cursor/skills/mark-buy-sell/scripts/mark_buy_sell.js --dry --from=2026-07-02

# 只标记指定周期（例如只标 1小时 和 4小时）
node .cursor/skills/mark-buy-sell/scripts/mark_buy_sell.js --from=2026-07-02 --periods=240,60
```

> `--from` 起始日期应与画笔时一致（脚本会读取该日期之后的笔数据来计算买卖点）。
> 小周期K线加载窗口与画笔同源：参数中心「基础组件 → 画笔」的「小周期绘制窗口」（`windowDays3/15/30S`），
> 手动调用时若参数中心有自定义值应加 `--chan-cfg=` 透传（导出方式见 chan-bi SKILL）。

### 参数说明

| 参数 | 说明 | 默认值 |
|------|------|--------|
| `--from=YYYY-MM-DD` | **必填**：起始日期，所有周期都从该日期开始计算笔和买卖点 | 无（缺少时报错退出） |
| `--periods=...` | 要标记的周期列表（逗号分隔，从大到小） | `D,240,60,15,3` |
| `--keep=N` | 每周期保留的标记总数（不分类：买+卖合并后只保留时间上最近的 N 个） | `10` |
| `--dry` | 只计算不绘图 | 关闭 |
| `--debug` | 打印一类落点/跳过过程、标记列表等调试信息 | 关闭 |

## 起始日期规则（每次标记必做，且必须输入日期）

**用户说「标记买卖点」时，必须先询问「起始日期」（格式 `YYYY-MM-DD`，如 `2026-07-02`），得到日期后再执行标记。不得在未获得日期的情况下直接运行脚本。**

```
① 询问：本次标记买卖点从哪个日期开始？（格式 YYYY-MM-DD，如 2026-07-02）
② 用户给出日期 → 运行 node mark_buy_sell.js --from=YYYY-MM-DD
③ 用户未给出明确日期 → 再次询问，直到获得日期后才执行
```

## 标记规则

### 标记前先清除旧标记

每次标记买卖点前，会先**清除已经存在的买卖点标记**：
- 脚本开始会依次切到各周期，删除所有标签为 `CHAN_BUYSELL_<周期>` 的图形
- 然后重新计算并在各周期绘制最新的买卖点

### 基于各周期的笔（强制读盘）

买卖点基于**各周期自己画的笔**计算：脚本读取 `chan-bi` 画笔 SKILL 落盘的
`.cursor/cache/bis_<品种>.json` 笔数据文件（该文件包含各周期已完成 ATR过滤、未完成笔延伸、
跨周期端点校准的最终笔，与图上所画笔完全一致），然后调用 `chan-core` 的买卖点算法计算并标记。

- 找不到笔数据文件 / 品种不匹配 → **报错退出**，提示先运行「画笔」；
- 某周期在笔数据文件中没有笔（画笔未覆盖该周期）→ 跳过该周期并提示；
- 仍会读取当前周期K线，仅用于：买卖点文字偏移量（ATR）、标记吸附到本周期bar边界（2026-10-14 规则v2 起 MACD 不再参与买卖点判定，计算与传参仅为兼容保留）。

### 买卖点定义（缠论，2026-10-14 规则v2：旧逻辑整体作废，备份=git 6971db6）

**总规则**：①**方向开窗管全部二三类点**——上级已收笔上涨笔窗 `(startTime, endTime]` 内小级别只标买点、下跌笔窗内只标卖点、未收笔尾段（最后已收笔终点之后）双向放行；一类点由生成笔方向天然合规不参与过滤。②**背驰不参与买卖点判定**（chan-core 的 isBiDiverge 仅用于收笔判定）。③**日线（无上级）不标买卖点**。

| 类型 | 定义（买侧表述，卖侧镜像） |
|------|------|
| 一买 | **已收笔上级上涨笔的起点 / 下跌笔的终点**，投影落到笔内部的小级别顶点（`lowerVertexOf` 阶梯：±1根K同价→覆盖窗同价→跨度同价→跨度内同角色极值）；同笔端点不标；尾段不补一类 |
| 二买 | **1买锚后低点逐一抬高**（首个与锚价比、其后与前一低点比；未抬高只更新参照不标）——首个抬低 = 2买。**强弱（用户口径）**：反弹=**1买后到该候选为止的最高点**、前高=**1买之前最近的顶点**——过前高=强二买、没过=弱二买（10-9 案例口径：反弹4143.425 vs 前高4184.385 → 弱二买）；只用已成结构，候选出现当下即判 |
| 类2买 | 2买之后与其**同一个中枢内**（按时间归属同一段盘整，价格区间会把常在枢外的主点漏掉）的后续回踩：抬高的标，没抬高但低点仍高于 1买锚的也标（已收上涨笔里第二次回踩可以略低于前低）；跌破锚价不标；不在同中枢的不标（交给三类规则） |
| 三买 | 价格**离开中枢上沿（上破 zg）之后，回踩不再进该中枢**（`price > zg - thirdZsTol`）——序号窗口（每个已收笔上级上涨笔、**窗口内重新起算**）内**第 1 个被向上离开的中枢**的首个合格回踩；本枢序列收到下一个已离开中枢的离开笔起点（含该时刻回抽；下一中枢未离开仍在三笔重叠完成处截断）；无中枢不标 |
| 类3买 | 同一个中枢离开后的其后合格回踩（回踩重进中枢则本轮结束，等待下一次离开；每枢计数不重置） |
| 4买 | 窗口内**第 2 个被向上离开的中枢**的首个合格回踩（与三类同构）；其后同枢回踩=**类4买**；≥3 个中枢封顶类4买 |
| 一卖 | 已收笔上级上涨笔的终点 / 下跌笔的起点（投影，同笔不标） |
| 二卖/类2卖 | 1卖锚后高点**逐一压低**：首个=2卖、同一中枢内后续=类2卖；强弱=反弹笔 vs 前低（过了前低=强） |
| 三卖/类3卖/4卖/类4卖 | 下破 zd 离开中枢后**反抽不再进该中枢**（`price < zd + thirdZsTol`）；序号制与买侧同构 |

**区间套原则（重要）**：
- 买卖点标记**必须以第一步画笔的结果（日线笔）为总框架**，逐级区间套；
- 各周期先保留区间套下识别出的全部买卖点（**同刻优先级：一类 > 二类族 > 三类族**——1买锚后首个抬低按定义就是2买，三类族不得抢占），最后**每周期不分类只保留时间上最近 10 个**标记（`--keep=N` 可调，买+卖合并计数）。

**强弱标签**：图表上 2买/类2买/2卖/类2卖 显示为 `强二买/弱二买/强类2买…`（`strong=null` 仅锚前无参照的防御态 → 弱先行）。

### 一类端点（跨周期）

| 周期 | 一类来源 |
|------|------|
| 日线 | **无上级，不标买卖点**（2026-10-14 规则v2；日线笔仍作为 4小时的上级参与区间套） |
| 4小时 | 日线已确认笔端点 → 落到 4小时级别顶点 |
| 1小时 | 4小时已确认笔端点 → 落到 1小时级别顶点 |
| 15分钟 | 1小时已确认笔端点 → 落到 15分钟级别顶点 |
| 3分钟 | 15分钟已确认笔端点 → 落到 3分钟级别顶点 |

够笔的形成段按已确认笔处理。相邻两笔共用的端点，只要其中一笔是同笔，这个端点就不标。

### 同笔不标

本周期某笔与上一级别某笔起终点的时间和价格都重合（`isSameAsUpperBi`，时间容差 = 本周期 1 根 K 线，价格容差 0.01），该上级笔的两个端点在本级别都不标 1买/1卖。时间容差取一个本周期 bar，是因为低级别端点落在更小周期边界、上级端点落在本周期边界，同一笔两端最多差一根本周期 K 线。

例：15分钟 8-14 16:12→21:39 与 1小时 8-14 16:00→21:30 同笔，15分钟不标这段的 1买/1卖。

### 大级别未成笔的尾段

上一级别最后一根已确认笔结束之后、还没走出新收笔的区段（含 enough 形成段——只要未收笔一律算尾段），里面的小级别**多空买卖点双向放行**：二三类族自然延伸进尾段（1卖/1买 锚来自已收笔末笔端点，天然存在）；**尾段不再补一类点**（一类只认已收笔上级笔端点，2026-10-14 规则v2）。

### 动态更新（区间套·笔区间粒度）

大级别有几笔发生变化时，从发生变化的最大周期开始，该周期和全部更小周期都变脏（`changedBiSpan`+`nestedDirtyPeriods` 级联，span 取并集）——**脏区间起点之前的旧标记沿用上次结果、之后取本次新算**；没变的更大周期整体沿用。每周期保留截断（`--keep`）在合并后的完整列表上做。图表侧把笔端点指纹存在 `.cursor/cache/buysell_<品种>.json`（逻辑版本 `20261015-third-until-next-leave`），逻辑版本变化时全量重算。

**加固（2026-10-14，9-26 堆积案）**：①早于已加载K线首根的标记跳过不画（防吸附堆积），下次历史加载完整后补画；②清除旧标后复核删净、未净重试（先收集 id 再删，最多 12 轮）并告警；③脚本实例互斥锁（`.cursor/cache/buysell_mark.lock`，陈旧10分钟自动接管）——防 webapp 自动任务与手动运行并发交错清/画留残渣。

## 显示规则

- **每周期最多显示最近 10 个标记**：买点+卖点合并按时间排序，每周期只保留时间上最近的 `--keep`（默认 10）个，不保证每类都有；
- 买卖点用**红色文字**标记（文本标签，如 `1买` `2买` `3买` `1卖` `2卖` `3卖`）；
- （2026-10-14 规则v3）**跨周期共振变绿已删除**：全部标记固定红色（color 字段保留恒红供 eval 比对兼容）；
- **只在该周期显示**：每个周期的买卖点通过 `intervalsVisibilities` 设置为只显示本周期（例如 4小时的买卖点只在 4小时 图可见，切到 1小时 自动隐藏），不会跨周期显示；
- 买点文字画在极值价格**下方**，卖点文字画在极值价格**上方**（偏移量按 ATR 自适应）；
- 标记不锁定，可自行编辑/拖动。

## 常见问题排查

| 问题 | 可能原因 | 检查命令 |
|------|----------|----------|
| ECONNREFUSED | TradingView 未以调试模式启动 | `netstat -ano \| findstr 9222` |
| 未找到页面 | 图表标签未打开 | 打开一张图表即可 |
| 提示缺少 --from | 未输入起始日期 | 必须询问用户起始日期后执行 |
| **报错「未找到 XX 的笔数据文件」** | 未先运行「画笔」SKILL（chan-bi），或缓存被清空 | 先对当前品种运行画笔（会生成 `.cursor/cache/bis_<品种>.json`），再运行本脚本 |
| **报错「笔数据文件属于 XX，与当前品种不一致」** | 缓存文件是其他品种画笔时生成的 | 先对当前品种运行画笔，再运行本脚本 |
| 某周期跳过（笔数据为空） | 画笔未覆盖该周期（如 `--periods` 未包含） | 用画笔 SKILL 重新画该周期 |
| 某周期没有一买标记 | 该笔与上级笔完全重合（同笔，由上级标记），或上级最近端点不是上涨笔起点/下跌笔终点（当前段无对应一类端点），或该笔跨度内小级别无任何顶点（无结构，保持上级时刻） | `--debug` 查看 `[一类跳过-同笔]` 与落点过程 |
| 一卖标在上涨途中（如 15分钟 8-17 10:00） | 该局部顶位于上级上涨笔内部、上涨仍在延续，一类点应已随上级上涨笔终点落在笔内部最高小级别顶点 | 切换上级周期核对上涨笔结束点 |
| 某周期一卖/一买未标 | 该端点属于与上级完全重合的同笔，同笔两端都不标；或该端点不是上级已确认笔的端点 | 对照上级笔起终点与 `isSameAsUpperBi` |
| 三买未标出 | 三买对每一笔二买后寻找（每段最多一个），需存在「突破前顶的上涨笔 + 其后第一个回调不破前顶」的组合，且回调须位于上级上涨笔内并高于该笔起点价；若回调跌破前顶、二买之后无创新高上涨段、或回调恰落在上级笔起点（新段启动点）则不标 | `--debug` 查看二买及前后笔结构 |
| 清除后旧标记还在 | 旧标记周期未在当前运行列表里 | 默认标记 D,240,60,15,3 全部周期 |

## 注意事项

- 脚本自动读取**当前图表**的品种和周期，切换品种后需重新运行。
- **必须先对该品种运行「画笔」**（chan-bi SKILL）生成笔数据文件，本脚本才能标记；否则报错退出。
- 本 SKILL 只负责买卖点标记，**不画笔、不清除笔**（画笔用 `chan-bi` SKILL）。
- 标记前会清除所有周期的旧买卖点（`CHAN_BUYSELL_*`），旧笔（`CHAN_BI_*`）不受影响。


## 预期笔与够笔运行笔（2026-09-17 更新）

下跌够笔且普通底分型右肩收盘后，预期上涨段立即参与下级买卖点、中枢归属和方向判断；卖侧镜像。合并后从起点块起满5块（含起点）才通过够笔门槛；进场预期够笔同样使用合并K线。活动端点不锚定已确认一类点，原始画笔缓存与结构视图分开。Python与JS共用同构 `buildStructureContext` / `mergedSegmentCount` 规则，详见 [统一规范](../../../../spec/plans/SPEC_structure_context.md)。
