# 缠论中枢绘制

通过 CDP 连接 TradingView Desktop，读取 **`chan-bi`（画笔）SKILL 落盘的笔数据**，按缠论中枢定义在图上画**中枢矩形**（颜色与该周期笔一致、仅本周期显示）。

> **算法来源**：所有缠论算法由 **`chan-core`**（`.cursor/skills/chan-core/scripts/chan_core.js`）提供（唯一算法源），本脚本只负责读取笔数据、调算法、绘制与落盘中枢数据。修改算法规则请改 `chan-core`。
>
> **强制依赖画笔数据**：本 SKILL **不计算笔**，**强制读取 `chan-bi` 画笔 SKILL 落盘的笔数据文件**（`.cursor/cache/bis_<品种>.json`）。如果文件不存在、或文件品种与当前图表品种不一致，脚本会**报错退出**，必须先对当前品种运行「画笔」（chan-bi）后再画中枢。

## 前置条件

1. TradingView Desktop 以调试模式启动：`TradingView.exe --remote-debugging-port=9222`
2. 已打开至少一张图表，且图表停留在**要画中枢的品种**上（脚本自动读取当前品种和周期）
3. chrome-remote-interface 已安装（在 `server-cdp/node_modules/`）
4. **已对该品种运行过「画笔」**（chan-bi SKILL），生成了 `.cursor/cache/bis_<品种>.json` 笔数据文件

## 使用方式

```bash
# 在图表上画中枢（必须指定起始日期，默认画 1小时(60) 的中枢）
node .cursor/skills/chan-zs/scripts/chan_zs.js --from=2026-06-30

# 只计算并打印中枢，不绘图（先验证再画，同样会落盘中枢数据）
node .cursor/skills/chan-zs/scripts/chan_zs.js --dry --from=2026-06-30

# 画多个周期的中枢（例如 4小时 和 1小时）
node .cursor/skills/chan-zs/scripts/chan_zs.js --from=2026-06-30 --zs-periods=240,60
```

> `--from` 起始日期应与画笔时一致（脚本读取该日期之后的笔数据来计算中枢）。

### 参数说明

| 参数 | 说明 | 默认值 |
|------|------|--------|
| `--from=YYYY-MM-DD` | **必填**：起始日期，与画笔 chan-bi 一致 | 无（不校验，仅用于落盘记录） |
| `--periods=...` | 周期列表（逗号分隔，从大到小），用于上级笔归属 | `D,240,60,15,3` |
| `--zs-periods=...` | 要画中枢的周期（逗号分隔） | `60` |
| `--dry` | 只计算不绘图 | 关闭 |
| `--debug` | 打印数据覆盖等调试信息 | 关闭 |

## 起始日期规则（每次画中枢必做，且必须输入日期）

**用户说「画中枢」时，必须先询问「起始日期」（格式 `YYYY-MM-DD`，与画笔时一致），得到日期后再执行。不得在未获得日期的情况下直接运行脚本。**

```
① 询问：本次画中枢从哪个日期开始？（格式 YYYY-MM-DD，与画笔一致）
② 用户给出日期 → 运行 node chan_zs.js --from=YYYY-MM-DD
③ 用户未给出明确日期 → 再次询问，直到获得日期后才执行
```

## 中枢定义（缠论）

### 分解原则（不跨周期）

- 中枢基于**各周期自己画的笔**计算：读取 `chan-bi` 画笔 SKILL 落盘的
  `.cursor/cache/bis_<品种>.json` 笔数据文件（该文件包含各周期已完成 ATR过滤、未完成笔延伸、
  跨周期端点校准的最终笔，与图上所画笔完全一致）；
- **不跨上级笔**：本级别中枢只能构建在「同一个上级笔」内部（如 1小时中枢必须完整落在
  同一个 4小时笔内）。用上级笔时间区间把本级别笔切段，每段内独立计算；
- **所有周期的笔完成后再画中枢**：中枢读取的是 chan-bi 已全部落盘的笔数据，
  计算与绘制过程中**不修改任何笔**。

### 至少 5 笔才画中枢

- 只有上下上/下上下 3 笔的中枢**不画**；至少 5 笔（含离开笔）才画。
- 扫描/延伸逻辑保留：三笔重叠形成中枢后向后延伸，出现离开中枢的笔时结束。

### 中枢区间（垂直）

- 取**构成中枢的全部笔（含离开笔）的重叠部分**：
  - `ZG = min(全部笔高点)`，`ZD = max(全部笔低点)`；
  - 如 8-25~8-27 的 5 笔（4697.105→4605.29→4673.765→4583.065→4643.21，离开笔 4643.21→4564.27）
    重叠区间 = `[4605.29, 4643.21]`。
- `GG`/`DD` 记录全部笔的绝对高点/低点。

### 中枢水平边缘（左右边缘）

**用户规则：`[进入笔最后一根K − 5, 离开笔第一根K + 5]`**，按**本周期**单根K线时长外扩：

- **左边缘** = 进入笔（三笔重叠形成中枢的第一笔）的**终点** − 5 根K（如 1小时中枢外扩 5 小时）；
- **右边缘** = 离开笔（中枢延伸结束后脱离中枢的笔）的**起点** + 5 根K；
- 中枢延伸到最后无离开笔时，右边缘 = 构成中枢最后一笔的终点 + 5 根K。

> 例（1小时中枢）：进入笔终点 = 8-25 21:45 → 左边缘 = 8-25 21:45 − 5 小时；
> 离开笔起点 = 8-27 10:00 → 右边缘 = 8-27 10:00 + 5 小时。

### 离开笔判定

中枢延伸扫描时，出现以下情况视为「离开中枢的笔」，中枢结束：
- 笔与中枢区间**完全无重叠**；
- 笔的**起点在中枢区间内、终点突破中枢边界**（如从中枢内向下跌破下沿的下跌笔、或从内部向上突破上沿的上涨笔）。起点在中枢区间外（另一侧）的穿越笔仍算延伸。

## 显示规则

- 中枢用**矩形**绘制，**仅边框不填充**；
- **颜色与该周期笔一致**：1小时=黄色 `#FFD700`、4小时=蓝色 `#2962FF`、15分钟=紫色 `#8A2BE2`、3分钟=青蓝色 `#00BCD4`、日线=红色 `#F23645`；
- **只在该周期显示**：每个周期的中枢通过 `intervalsVisibilities` 设置为**只显示本周期**（如 1小时的中枢只在 1小时 图可见，切到 4小时/15分钟 自动隐藏），不会跨周期显示；
- title 打上源周期标签 `CHAN_ZS_<周期>`，再次画中枢时按标签只清除本周期旧中枢；
- 中枢在「低一级校准基准周期」上创建（与笔一致，使端点落在基准周期 bar 边界，跨周期极值位置精确重合）。

## 常见问题排查

| 问题 | 可能原因 | 检查命令 |
|------|----------|----------|
| ECONNREFUSED | TradingView 未以调试模式启动 | `netstat -ano \| findstr 9222` |
| 未找到页面 | 图表标签未打开 | 打开一张图表即可 |
| **报错「未找到 XX 的笔数据文件」** | 未先运行「画笔」SKILL（chan-bi），或缓存被清空 | 先对当前品种运行画笔（会生成 `.cursor/cache/bis_<品种>.json`），再运行本脚本 |
| **报错「笔数据文件属于 XX，与当前品种不一致」** | 缓存文件是其他品种画笔时生成的 | 先对当前品种运行画笔，再运行本脚本 |
| 某周期没有中枢 | 该周期笔数不足 5 笔，或笔未完整落在同一个上级笔内 | 用 `--dry` 查看各周期中枢计算日志 |
| 清除后旧中枢还在 | 旧中枢周期未在当前运行列表里 | 默认画 60 周期；如需其他周期用 `--zs-periods=...` 指定 |

## 注意事项

- 脚本自动读取**当前图表**的品种和周期，切换品种后需重新运行。
- **必须先对该品种运行「画笔」**（chan-bi SKILL）生成笔数据文件，本脚本才能画中枢；否则报错退出。
- 本 SKILL 只负责中枢标记，**不画笔、不清除笔**（画笔用 `chan-bi` SKILL）。
- 画中枢前会清除所有周期的旧中枢（`CHAN_ZS_*`），旧笔（`CHAN_BI_*`）不受影响。
