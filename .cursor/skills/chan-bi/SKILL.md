# 缠论画笔

通过 CDP 连接 TradingView Desktop，读取当前图表K线，按缠论理论（包含处理 → 分型识别 → 笔构建）在图上**画线段（笔）**。

> **算法来源**：所有缠论算法由 **`chan-core`**（`.cursor/skills/chan-core/scripts/chan_core.js`）提供（唯一算法源），本脚本只负责取K线、调算法、绘制与**落盘笔数据**。修改算法规则请改 `chan-core`。
>
> **中枢绘制已拆分**：缠论中枢（矩形）由独立的 **`chan-zs`** SKILL（`.cursor/skills/chan-zs/`）绘制——它读取本脚本落盘的笔数据 `.cursor/cache/bis_<品种>.json` 来计算并绘制中枢。本脚本只画笔，不画中枢。

## 前置条件

1. TradingView Desktop 以调试模式启动：`TradingView.exe --remote-debugging-port=9222`
2. 已打开至少一张图表，且图表停留在**要画笔的品种**上（脚本自动读取当前品种和周期）
3. chrome-remote-interface 已安装（在 `server-cdp/node_modules/`）

## 使用方式

```bash
# 在图表上画笔（必须指定起始日期，一次画出 日线/4小时/1小时/15分钟/3分钟 五个周期）
node .cursor/skills/chan-bi/scripts/chan_bi.js --from=2026-07-02

# 只计算并打印笔，不绘图（先验证再画，同样会落盘笔数据）
node .cursor/skills/chan-bi/scripts/chan_bi.js --dry --from=2026-07-02

# 指定K线数量（仅未指定日线起点时生效）
node .cursor/skills/chan-bi/scripts/chan_bi.js --bars=300

# 只画指定周期（例如只画 1小时 和 日线）
node .cursor/skills/chan-bi/scripts/chan_bi.js --periods=60,D

# 调试：打印分型序列和处理过程
node .cursor/skills/chan-bi/scripts/chan_bi.js --dry --debug
```

> **笔数据落盘**：每次画笔（含 `--dry`）都会把各周期的最终笔数据写入
> **`.cursor/cache/bis_<品种>.json`**（品种名中的 `:` 等特殊字符替换为 `_`，如 `TVC:UKOIL` → `bis_TVC_UKOIL.json`）。
> `mark-buy-sell`（买卖点）SKILL **强制依赖**该文件——先画笔落盘、再标记买卖点。

### 参数说明

| 参数 | 说明 | 默认值 |
|------|------|--------|
| `--from=YYYY-MM-DD` | **必填**：日线起点日期，所有周期都从该日期开始画笔 | 无（脚本兜底取最近 N 根日K，但按规则调用时必须传入） |
| `--bars=N` | 取最近 N 根K线（仅未指定日线起点时，最外层日线使用） | `200` |
| `--atr=K` | ATR 过滤系数（幅度 < K×ATR 的笔剔除） | `0.5` |
| `--gap=K` | 跳空独立成笔阈值（相邻K线缺口 ≥ K×ATR 时强制独立成笔） | `1.0` |
| `--periods=...` | 要绘制的周期列表（逗号分隔，从大到小） | `D,240,60,15,3` |
| `--with-30s` | 追加 30 秒级别（30S）：**只计算并落盘笔数据、不在图上绘制**（30s 笔太密），供 `mark-entry --with-30s` 的「以下级别背驰」使用。30S 只取最近 3 天数据（密度为 3 分钟的 6 倍）。关闭后重跑本脚本（不带该参数），落盘文件中的 30S 数据即随之移除 | 关闭 |
| `--dry` | 只计算不绘图 | 关闭 |
| `--debug` | 打印分型序列、回溯过程及数据切换日志 | 关闭 |

## 起始日期规则（每次画笔必做，且必须输入日期）

**用户说「画笔」时，必须先询问用户「日线起点日期」（如 `2026-07-02`），得到日期后再执行画笔。不得在未获得日期的情况下直接运行脚本。**

```
① 询问：本次画笔从哪个日线日期开始？（格式 YYYY-MM-DD，如 2026-07-02）
② 用户给出日期 → 运行 node chan_bi.js --from=YYYY-MM-DD
③ 用户未给出明确日期 → 再次询问，直到获得日期后才执行
```

- **所有周期（日线/4小时/1小时/15分钟/3分钟）都从该起始日期开始画笔**；
- **小周期窗口限制**：3分钟周期只绘制最近 15 天、15分钟周期只绘制最近 30 天、30秒（`--with-30s`）只取最近 3 天
  （以最新K线时间往前推），其余周期从起始日期全量绘制。避免小周期从起始日期到最新的
  全部笔堆叠导致图上过密；同时 3分钟 只需加载最近 15 天数据即可，不再为覆盖起始日期
  加载数月完整历史而超时跳过。落盘笔数据同样只含窗口内笔，`mark-buy-sell` 等只标记窗口内的买卖点；
- 若当前周期数据未覆盖起始日期（默认只加载最近 300 根K线），脚本会调用
  `scrollToFirstBar()` 自动加载完整历史，直到数据起点早于起始日期，再从中取K线；
- 若用户给出的日期在该品种K线范围之外，脚本会提示该日期之后没有K线数据并跳过。

## 多周期画笔规则（从大到小嵌套迭代）

**默认按从大到小顺序一次画 日线 → 4小时 → 1小时 → 15分钟 → 3分钟 五个周期。**

> 按「起始日期规则」要求，每次调用必须传入起始日期（`--from=YYYY-MM-DD`）。
> 下面"未指定日期"的分支仅为脚本内部兜底机制，不作为调用方式。

- **指定了起始日期（--from）**：所有周期都从该日期开始画笔（各周期独立取
  「日期之后 + 前30根缓冲」的K线计算，只画结束时间 ≥ 该日期的笔）；
- **未指定日期**：各周期以上层最后一笔为锚嵌套迭代绘制（兜底行为）。

执行流程（脚本内部自动完成）：

```
第1层 日线(D)    从起始日期(--from)开始 或 取最近 N 根日K，画日线笔
  └─ （未指定日期时）取日线「最后一笔」的起点作为锚点
第2层 4小时(240) 在起始日期之后 或 锚点之后的4小时K线上画内部笔（前补30根缓冲保证分型完整）
  └─ 取4小时「最后一笔」的起点作为新锚点
第3层 1小时(60)  在起始日期之后 或 锚点之后的1小时K线上画内部笔
  └─ 取1小时「最后一笔」的起点作为新锚点
第4层 15分钟(15) 在起始日期之后 或 锚点之后的15分钟K线上画内部笔
  └─ 取15分钟「最后一笔」的起点作为新锚点
第5层 3分钟(3)   在起始日期之后 或 锚点之后的3分钟K线上画内部笔（最内层，聚焦到最新行情）
第6层 30秒(30S)  仅 `--with-30s` 时追加：同样锚定 3分钟 最后一笔，只取最近 3 天数据计算
完成后自动切回原周期
```

> **小周期窗口**：15分钟 只绘制最近 30 天、3分钟 只绘制最近 15 天的笔（按最新K线时间往前推，
> `DRAW_WINDOW_DAYS` 配置），其余周期从起始日期全量绘制。窗口过滤在笔计算、端点校准、
> 区间套对齐完成后执行，只影响绘制数量，不影响算法正确性；过滤后的笔即为落盘与后续标记的依据。
>
> **30秒级别（`--with-30s`，可选）**：30S 密度是 3 分钟的 6 倍，只取最近 **3 天**数据；
> **只计算并落盘、不在图上绘制**（30s 笔太密，画图不可读），锚定/对齐/窗口过滤等
> 笔计算逻辑与其他周期完全一致。落盘后 `mark-entry --with-30s` 可用 30S 背驰给
> 3 分钟状态产生进场信号。不传该参数重跑一次，落盘文件即不含 30S（随时取消）。

细节说明：
- **锚点** = 上层最后一笔的起点（如日线最后一笔从 8-5 开始，4小时就画 8-5 之后的内部笔）；
- **缓冲**：锚点前额外取 30 根K线参与分型计算，避免窗口起点截断导致分型不完整，但**只绘制结束时间在锚点之后的笔**；
- **数据不足**：若锚点之后K线少于 20 根，则自动向前扩展上层更早的笔，直到数据足够；
- 每个周期独立计算、独立清除（只清自己的 `CHAN_BI_XX` 标签），互不影响；
- 每层绘制时打上源周期标签 + 可见范围，切换周期时按「跨周期显示规则」自动显示/隐藏；
- 只画指定周期时用 `--periods=60,D`（注意顺序按从大到小传入）。

## 缠论算法流程

```
原始K线 → ⓪长影处理 → ①包含关系处理 → ②分型识别 → ③笔构建 → ④端点极值修正 → ⑤ATR过滤 → ⑥未完成笔延伸 → ⑦时间校准 → ⑧区间套对齐 → 页面绘制
```

### ⓪ 长影处理（插针压平）

影线占振幅 ≥70% 且长度 ≥0.5×稳定ATR（全窗口 TR 均值，非尾部 14 根 ATR）的插针K线先压平，避免污染结构：
- 冲高插针（长上影）压平 high；但若该 bar 的 low 不低于左右相邻原始K线低点，影线价保留为 `_topCand`，该 bar 成顶分型中心时可用影线价作端点价（冲高针也有资格当顶）；
- 探底插针（长下影）压平 low，真低记入 `_origLow/_origLowTime`，供④端点极值修正恢复。
- 细节与案例见 chan-core/SPEC.md §2.0。

### ① 包含关系处理（合并K线）

相邻K线有包含关系时合并：
- **向上合并**取「高高」（最高取大、最低取大）
- **向下合并**取「低低」（最高取小、最低取小）

关键点：每根合并K线额外记录 `highTime`/`lowTime`（极值所在的**原始K线时间**），
确保顶分型落在真正最高价的K线时间上，而不是包含区间最后一根K线。
同时保留 `rawHigh/rawLow`（覆盖原始K线的真实极值，跳空检测用）、`_rawCount`（覆盖根数），
`_topCand/_origLow` 随合并传播（见 chan-core/SPEC.md §2.1）。

### ② 分型识别

- **顶分型**：中间K线最高，且整体高于左右 → 时间取 `highTime`
- **底分型**：中间K线最低，且整体低于左右 → 时间取 `lowTime`
- 顶分型中心带 `_topCand` 影线保留价时，端点价优先用它（见 chan-core/SPEC.md §2.2）

### ③ 笔构建（交替分型序列 + 回溯替换）

- 阶段一：构建**严格交替**的分型序列（连续同类型：顶取最高、底取最低）；
  与上级笔端点方向一致且价差 ≤0.001 的分型打 `locked` 标记，阶段二不可吞
  （区间套锁定，见 chan-core/SPEC.md §2.4.1）
- 阶段二：若相邻异类型分型间隔不足（合并K线间隔 < 4 或 覆盖原始K线 < 5），
  作废中间分型，让更极端的后续分型**回溯顶替**前一同类型分型。
  **回溯保护**：`prev→last` 已构成有效笔（间隔 ≥ 4 且无更极值且范围脱离）时前顶/前底
  不被顶替（如 8-20 04:00 顶→20:00 底间隔 11 根的坚实笔）；**例外（最小间隔脆弱笔）**：
  间隔恰为最小值 4 且回调/反弹 < 前段涨跌幅 50% 时，该笔尚未确认，随后创新高/新低
  说明整段仍是同一笔的延伸，前顶/前底仍被顶替（缠论：顶被更高顶突破即作废）。
  例：15分钟 9-3 顶 4496.01(21:03)→底 4466.02 间隔恰 4、回调 39%（浅），23:15 新高
  4510.93 顶替前顶，上涨笔延伸至 4510.93；对称场景 8-19 底 4327.27 被 09:00 更低底
  4324.68 顶替、下跌笔延伸到真实低点（旧画法笔内藏着更极值）。
- 阶段三：两两连笔，首尾自然连续。
- **分型范围脱离**：一笔的两端分型不能互相"包含"。
  - 起点侧看**与段同侧的两根**：下跌笔的底分型必须低于「顶分型中心与右 bar」的最低点
    （顶分型左 bar 的低点不参与——它是顶之前主升前夜的旧低点，用它会误杀健康反弹底，
    例：60m 7-14 20:00 顶 4104.05 的左 bar 19:00 低点 4015.485 只比 7-15 16:00 真实底
    4017.475 低 2 点，旧"三根"规则使该底被拒、整段反弹消失）；上涨笔对称。
  - 终点侧看**三根（防反向吞没）**：下跌笔底分型三根K线最高价不得涨回起点顶价之上，
    上涨笔顶分型三根K线最低价不得跌破起点底价（顶/底后立即反向贯穿起点的中继弱反弹不成笔）。
  - 即使合并K线间隔 ≥ 4 且覆盖原始K线 ≥ 5，只要分型范围未脱离，也不成笔，
    等待后续更极端的分型或并入更大的笔。
  - 细节与 240 8-28 崩盘案例见 chan-core/SPEC.md §2.4.4。
- **跳空独立成笔**：相邻（合并后）K线之间存在幅度 ≥ `K×ATR` 的跳空缺口时，
  强制在缺口处独立成笔（不受最小间隔/极值规则限制，跳空段无K线，缺口本身即一段独立走势）；
  该笔端点会被 **锁定**（gapLocked）：
  - 后续同类型分型**严格突破**（新高 > 锁定顶 / 新低 < 锁定底，不是 ≥/≤）锁定价格时
    解锁并替换（跳空笔并入更大趋势，符合"笔必须含该笔极值"）；
  - 未突破则保留独立笔；
  - 锁定的笔不参与「未完成笔延伸」。
  默认 `--gap=1.0`（约 1 倍 ATR，只对显著跳空生效，避免小缺口碎化大级别趋势）。
- **近等双顶/双底平台取后顶/后底**（仅 1h 及以上周期开启）：平台里两个几乎同价的
  高点，取更晚的那个，前面的视为插针（走势终完美）。条件：差价 ≤ max(0.3×ATR, 0.1%×价)、
  两分型之间所有相邻分型间隔 <4（整段拆不出笔的平台/直拉）、中间有过 ≥同阈值的真实回调、
  单跳封顶；locked/gapLocked 端点不参与，macdCross 端点不豁免
  （见 chan-core/SPEC.md §2.4.2-2，例：1h 8-31 顶 4464.23 → 9-1 顶 4461.7）。
- **MACD 变色成笔**：相邻异类型分型**间隔不足**（合并K线间隔恰 3，即合并后共 4 根）时，
  若该区间内 K 线对应的 **MACD 柱发生方向性红绿转换**（底到顶绿变红 / 顶到底红变绿），
  则视为一段独立的动能切换走势，**允许间隔不足也成笔**：
  - **对覆盖原始K线数不设下限**（`macdRaw` 仅记录覆盖数）；
  - 仍要求 `noMoreExtremeInside`（笔端点必须是该笔区间内极值），避免画出"笔内藏更极值"的非法笔；
  - **MACD 端点让位**：MACD 变色成笔的端点若被后续更极端的同类型分型超越
    （如 92.83 之后又跌破到 92.74），让位更新为该更极端端点并移除中间分型，
    保证 MACD 变色成笔终点是区间内最新的绝对极值；
    让位前须检查整笔内部无越界价格（新旧端点之间的合并K线与中间分型不得越过笔两端价，
    `replacementExtremesClear`，见 chan-core/SPEC.md §2.4.4）；
  - 该笔带 `macdCross` 标记（仅用于结果展示），并记录覆盖原始K线数 `macdRaw`，
    不锁定、不影响其他规则。
- **前顶/前底作废（弱分型突破）**：`prev2`（结果中倒数第二）与当前分型 `k` 同类型，
  且 `prev2 → last` 不构成有效笔（间隔不足，`prev2` 是脆弱端点），
  而 `k` 比 `prev2` 更极端（创新高/新低）时，`prev2` 作为笔端点已被市场否定
  （缠论原则：顶被后续更高顶突破则前顶作废，底被后续更低底跌破则前底作废），
  让 `k` 顶替 `prev2` 并移除中间的 `last`，使上涨/下跌笔延续到 `k`。
  例：3分钟 8-12 11:18 顶(89.84) 被 12:00 顶(90.07) 突破，上涨笔画到 90.07@12:00。
  **为避免误伤真实顶/底，必须同时满足**：
  1. `last` 不得比 `prev3`（结果中倒数第三）更极端（否则 `last` 是深回调的真实转折点）；
  2. 回调/反弹必须浅：`pull < 上涨幅度×50%`（或 `bounce < 下跌幅度×50%`），
     深回调意味着 `prev2` 是真实顶/底；
  3. `last` 必须是**弱分型**：`macdCross === true && macdRaw < 5`
     （不足 5 根原始K线、靠 MACD 变色凑数的微回调停顿，最容易被后续突破否定）。
     例：1小时 7-22 23:00 底(MACD成笔 raw=7) 结构充足，7-22 17:00 顶是真实顶，不作废。

### ④ 端点极值修正（fixBiExtremes）

被包含合并或长影压平藏起来的真实极值，恢复为笔端点：底终点从分型中心起扫（中心只认
`_origLow`、中心之后认 `_origLow ?? rawLow`），顶终点从中心之后起扫只认 `rawHigh`；
命中后本笔终点与下一笔起点同步平移（保持首尾连续）；`gapLocked` 笔端点固定不修正。
细节见 chan-core/SPEC.md §2.4.5。

### ⑤ ATR 过滤

剔除幅度 < `K × ATR` 的噪音小笔（默认 K=0.5；阈值基准用全窗口 TR 均值，而非尾部
14 根 ATR，见 chan-bi/SPEC.md 3.3 第 5 步）。

### ⑥ 未完成笔延伸

缠论要求最新一笔延伸到当前K线：当最后一笔方向上的极端价出现在窗口末尾
（如末端一波单调上涨/下跌，高点/低点不断刷新而**无法形成新的顶/底分型**），
把最后一笔的终点推进到该极端价所在K线。
- 只处理最后一笔，不改变已定型的旧笔；
- `gapLocked` 跳空锁定笔不参与延伸；
- 例如日线 78.11(8-5) 起笔，若 8-14 之后单调上涨至 8-21 的 94.83 而无顶分型，
  最后一笔会正确画到 **8-21 的 94.83**，而不是停在中间的小高点。

> **买卖点识别已停用**：本 SKILL 当前只画线段（笔），不再在图上绘制一买/二买/三买、
> 一卖/二卖/三卖标记。买卖点算法已统一收敛到 **`chan-core`**（`findBuyPoints`/`findSellPoints`），
> 由 `mark-buy-sell` SKILL 调用并在图上标记（本脚本已删除历史版本的买卖点函数）。

### ⑦ 跨周期端点时间校准（逐级校准）

大周期K线的时间戳是 **bar 起点**，其内部最高/最低点可能发生在更晚的低一级K线上
（例如 1小时 20:00 这根 bar 的最高点 94.71 实际出现在 15分钟 20:15 的K线）。

为让不同周期对同一极值的标记位置在图上**重合**，画完笔后对端点时间做**逐级校准**：

| 周期 | 校准基准（低一级） | 说明 |
|------|--------------------|------|
| 15分钟 | 3分钟 | 用3分钟K线确定极值精确位置 |
| 1小时 | 15分钟 | 用15分钟K线确定极值精确位置 |
| 4小时 | 1小时 | 用1小时K线确定极值精确位置 |
| 日线 | 4小时 | 用4小时K线确定极值精确位置 |
| 3分钟 | 无 | 已是最低级别，不校准 |

校准逻辑：找到端点所属的大周期bar，在其覆盖的低一级K线中，
取「价格达到该端点极值且时间最晚」的一根，作为该端点的绘制时间。

示例：UKOIL 8-20 的最高点 94.71
- 1小时周期画笔：端点画在 **8-20 20:15**（用15分钟校准）
- 15分钟周期画笔：端点画在 **8-20 20:21**（用3分钟校准）

校准基准K线按需加载并缓存（`refCache`），起点与 `--from` 保持一致。

> **绘制前数据覆盖保障**：加载校准基准需要把图表切到低一级周期再切回本周期，
> 切换后图表可能只加载了最近 N 根K线。若此时直接绘制较早的笔，端点时间戳超出
> 数据范围的会被 TradingView 吸附到数据边缘（表现为端点 `index:0`、时间错乱，
> 即「无效的笔」）。因此绘制前会检查图表第一根K线是否早于最早笔的时间，
> 未覆盖则 `scrollToFirstBar` 加载完整历史后再绘制（`ensureBarsCover`）。
> **注意：判断「数据已加载到最早」不能只看 `len` 是否稳定**——`scrollToFirstBar`
> 触发加载后数据是分批推进的，`len` 短暂稳定可能只是加载中途暂停。必须同时要求
> 「首根K线时间也连续多次不变」才认定加载完成，否则会提前退出，导致早期笔端点
> 全部被吸附到已加载数据边缘（曾出现 15分钟 175 笔中 171 笔端点全部错乱到 8-21）。
> 同时，`--from` 起始日期的覆盖判断允许 K 线起点与起始日 00:00 存在小偏差
> （实际第一根K线通常晚于起始日 00:00），避免数据起点晚于起始日几小时就被误判为
> "未覆盖"而反复加载直至超时跳过该周期。

> **基准周期绘制（bar 边界吸附）**：TradingView 的 polyline 只支持把点**精确**放在
> 「当前图表周期」的 bar 边界上；若传入的时间不在当前周期的 bar 边界（如 4小时周期
> 下传入校准后的 1小时 22:00），会被自动吸附到**所在 bar 的起点**（4小时 20:00），
> 导致跨周期校准失效、极值点位置回退。因此创建某周期的笔时：
> - **清除**旧笔在**源周期**进行（该周期自己的笔在源周期一定可见，能按 title 删干净）；
> - **创建**新笔切到**校准基准周期**进行（有校准基准的周期：日线在4小时创建、4小时在
>   1小时创建、1小时在15分钟创建、15分钟在3分钟创建、3分钟无基准就在本周期创建），
>   使校准后的端点时间正好落在基准周期的 bar 边界上，跨周期极值位置与基准周期精确重合。

### ⑧ 区间套强制对齐与断口治理（alignBiToUpper）

上级笔端点在本级必须复现：本级拐点时间/价格向最近上级拐点对齐；上级极值在本级对应
时间段K线中不存在（跨周期数据源聚合差异）时视为幽灵端点，跳过对齐；对齐造成的断口
再经合并与补幅度过滤治理。细节见 chan-core/SPEC.md §2.4.6。

## 跨周期显示规则

每笔创建时会通过 `intervalsVisibilities`（大类开关 + from/to 精确范围）限制可见周期：
**某周期的笔只显示在「该周期 + 低一级周期」，其余周期自动隐藏**。

| 在某周期画笔 | 该笔可见的周期 |
|------|------|
| 3分钟 | 30秒、3分钟 |
| 15分钟 | 3~15 分钟（3m、5m、15m） |
| 1小时 | 15分钟、1小时 |
| 4小时 | 1~4 小时（1h、2h、4h） |
| 日线 | 4小时~1天（4h、1D） |
| 周线 | 1天~1周（1D、1W） |

例如：
- 在 **3分钟** 周期画笔 → 切到 **30秒** 能看到青蓝色线段，切到 **15分钟及以上** 则自动隐藏；
- 在 **1小时** 周期画笔 → 切到 **15分钟** 能看到黄色线段，切到 **4小时/日线** 则自动隐藏；
- 在 **15分钟** 周期画笔 → 切到 **3分钟** 能看到紫色线段，切到 **1小时及以上** 则自动隐藏；
- 切换周期后 TradingView 根据每个图形上保存的可见范围自动显示/隐藏，无需重新运行脚本。

注意：分钟范围 3~15 / 小时范围 1~4 是连续的，因此中间的 5分钟、2小时等周期也会显示该级笔；这是周期可见性范围设计的固有行为。

## 按周期清除规则

每笔创建时都会打上**源周期标签**（存在图形的 `title` 属性，如 `CHAN_BI_60`）。

再次画笔时，**只清除当前周期**的旧笔：
- 只删除标签为 `CHAN_BI_<当前周期>` 的图形
- **不会删除其他周期画的笔**（例如在 15 分钟画笔，1 小时画的黄色笔会保留）
- 买卖点标记不在本 SKILL 处理范围内（脚本不绘制、不清除买卖点）

如需彻底清空某个品种上所有周期的缠论标记，需手动逐周期重画（或用对应周期各执行一次）。

## 常见问题排查

| 问题 | 可能原因 | 检查命令 |
|------|----------|----------|
| ECONNREFUSED | TradingView 未以调试模式启动 | `netstat -ano \| findstr 9222` |
| 未找到页面 | 图表标签未打开 | 打开一张图表即可 |
| 模块找不到 | chrome-remote-interface 路径不对 | 确认 `server-cdp/node_modules/` 存在 |
| 笔数量异常少 | 回溯替换过度合并 | 用 `--debug` 查看阶段二回溯日志 |
| 顶/底落在错误的K线 | 极值时间记录缺失 | 确认 `highTime`/`lowTime` 已正确更新 |
| 某周期的笔大量错乱、端点堆在同一个时间点 | 创建时图表数据未覆盖早期端点时间（`ensureBarsCover` 提前退出，图表重载/数据加载停顿时易发；60分钟在15分钟图创建需加载 2 个月数据最易中招） | 已修复：① 覆盖加载多轮重试且未覆盖时**裁剪超范围笔不画**；② 创建后**回读校验**端点，被吸附的笔自动删除重建重试，仍失败计入 `bi_bad` 报告（不再出现全绿假象） |
| 3分钟周期「无K线数据或切换失败，跳过」 | 为覆盖起始日期需加载数月完整历史（如 5 个月约 7 万根3分钟K线）而超时 | 已修复：3分钟 只需加载最近 15 天数据即通过覆盖检查（小周期窗口），不再加载完整历史 |
| 小周期（15分钟/3分钟）图上笔过多、过密 | 从起始日期到最新的全部笔堆叠（如 15分钟 5 个月 545 笔） | 3分钟 只绘制最近 15 天、15分钟 只绘制最近 30 天（窗口过滤） |
| 清除后其他周期的笔还在 | 这是**按周期清除**的正常行为 | 该笔标签是其他周期，需在其源周期画笔才会被清除 |

## 注意事项

- 脚本自动读取**当前图表**的品种和周期，切换品种后需重新运行。
- 本脚本只画线段（笔），不绘制、也不清除买卖点标记；页面上遗留的买卖点箭头如需清理，需单独处理（本 SKILL 不包含该操作）。
- 跨周期保留的笔按**绘制时的周期颜色**区分：同一图上黄色=1小时笔、紫色=15分钟笔，以此类推。
- 不同周期各自维护自己的笔集合，互不影响清除；切换周期后各周期可见范围内的笔会自动显示。
- 可见范围通过图形的 `intervalsVisibilities` 实现（源周期 + 低一级周期），由 TradingView 在切换周期时自动计算显示/隐藏。
