# 缠论 WEB 工作台操作指南

启动：`python -m py_chain.webapp --port 8000`，浏览器打开 `http://127.0.0.1:8000`。

## 导航

模块分两大类（2026-09-29 起，分层注册表 `py_chain/module_registry.py`；同日二轮调整后）：**基础公用组件**（画笔、画中枢、买卖点——各策略共用的结构计算）与**交易策略**（当前唯一「缠论V1」= 支阻位 + 交易计划 + 标记进出场三步，支阻参数按策略经方案列表单选生效；未来新策略在流程/参数树中以新组并列出现）。

- **分析工作台**：目标图表、起始日期、**交易策略**（下拉，当前：缠论V1）、更新控制、完整分析流程（按「基础结构组件 / 交易策略」两组显示）与模块详情。
- **回测与监控**：全量回测、K线回放、**MT5实盘**（监控页，2026-09-29 起替换原「实时监控」入口——显示进程在线状态、策略、持仓与盈亏汇总，多策略按 TAB 分离，含每策略「开启/关闭交易」开关；启动/停止实盘进程走 live_trader CLI，见 LIVE_GUIDE.md）和信号列表功能。图表驱动的实时监控仍可直连 `/modes.html?mode=live`。
- **基础数据**：拉取 TradingView 各周期历史K线到本地存储，供回测离线取数。
- **参数配置**：分模块参数中心（2026-09-15 起）。工作台左侧导航「参数配置」带**分组子菜单**（2026-09-29 三轮起）：**基础组件**（画笔/画中枢/买卖点）与**交易策略·缠论V1**（支阻位/交易计划/进出场）——子菜单切换分组，页内横向TAB选模块（切换分组不重载页面，未保存编辑不丢；直连 /params.html 无分组=全部平铺）。**支阻位**页（原手动调参、自动调参；来源逐周期可选「系统计算（密集区）/人工输入」，黄金分割/BOLL 为独立叠加开关；**方案列表每品种单选一个「生效」方案**（2026-09-29 起，复制语义：生效=该方案参数复制为本品种策略所用支阻参数，单选覆盖、再点取消；Excel 导入导出按钮已移除，接口保留）；**时点+回溯**口径（2026-09-26 起，取代旧「起始日期=窗口起点」）：「时点」=计算该时刻当下的支阻位（纯日期=**上海时间**当日 23:59:59；带时分=**上海时间**精确截断、自动对齐 3 分钟格；空=当下最新），「向前K线根数」限定**密集区候选**的回溯窗口（每周期各自计数，默认 300、0/空=不限）；**fib=末段趋势侧分割**——参照段必须已成笔（形成中且合并K不足 5 根：已离开末根则用最后一根已确认笔，还贴在末根上则用再前面的推动笔及其真实高低点）；价格回撤末笔时取**倒数第二根笔**（与回撤同向的推进笔）、延伸末笔时取末笔本身：下跌段→反弹阻力 RES（低位+r×波幅）、上涨段→回撤支撑 SUP（高位−r×波幅），各 3 条，与白名单买卖点无关；BOLL 轨道与时点价天然当下不受限。**调参页 BOLL 含末根K线**（2026-09-27 起，经 engine_extra 通道，与 TV 当前 bar 值同拍；回测/分析/CLI 仍为已收盘口径、信号基线不变）。**引擎已同步**（2026-09-26 用户拍板）：三模式回测与分析页经参数桶读同款 `lookbackBars`/末段 fib 口径（engine_kwargs_of 统一映射），回测信号已随口径变化重新定基；live 实盘不传 sr 参数仍为旧口径（例外，如需另做）；品种为**多选下拉**（2026-09-24 起，同回测卡口径）：勾多个=统一参数逐品种计算，单品种失败不拦其余，结果表按品种页签切换，「画图」画当前查看品种——画前自动把图表切到该品种且不切回；工作台分析仍按目标图表单品种计算）＋**缠论核心**（CHAN_CFG：跳空成笔、长影剔除、背驰时长、近等双顶〔容差 ATR/比例/固定价差三项并集 + 每周期开关〕、M1/M2/M4 开关等）＋**买卖点**（邻近合并阈值、每周期保留数）＋**进出场**（近支阻阈值、手数、滑点、出场门槛、出中枢衰减）＋**交易计划**（震荡判定阈值）。
  - 保存即持久化（`web/module_params.json`，只存与代码默认不同的键），**下一轮任务生效**；缠论核心为全局参数、保存后立即生效（有任务运行中会拒绝保存，先停止再改）。
  - 手数/滑点/近支阻等参数原回测卡片与工作台输入框已移除，此处为唯一编辑入口；历史方案对比表仍显示各方案保存时的取值。
- **使用指南**：常见操作、异常解释及六个模块规则入口。

原三模式界面可直接访问 `/modes.html`，支阻位界面保留 `/sr.html`（`/params.html` 参数中心的支阻位页签内嵌它），基础数据界面保留 `/data.html`。

## 基础数据（历史K线存储）

按品种合并累积存储到 SQLite（`data/bars.db`，同时间戳冲突取新值），回测页"数据源=本地数据存储"直接取数，无需 TradingView 运行。

- **拉取**：填品种/周期/起始日期（结束日期可空=到最新，可拉历史中段窗口），点"拉取并入库"。需 TD 运行；与三模式/标记/分析互斥，期间它们的启动会被拒绝。
- **拉取方式**：
  - *自动（推荐）*：先实时图表拉取；小周期按已存时间轴**分段补缺**（前缺/中洞/尾缺，间隔>5天算缺）自动转 Bar Replay 回放定位补拉——逐段定位到目标日期往回逐块取数，实测 3m 可回放至 2006-03，每块约2个月、即时入库，停止/失败后已拉部分保留，下次重查缺段自动断点续拉。
  - *仅实时*：只用实时图表，快但小周期深度受限。
- **查询**：**存储汇总**一表呈现——顶部概览指标（品种/总根数/最早最新），每品种×周期行含根数/跨度/首末/最近更新（该周期自身的入库时间，只随本周期刷新）/月度覆盖条（稀疏月标红、空月虚线）/缺口列表（相邻K线间隔>5天才计入，周末/假日休市不计入，口径与自动补拉一致），可按品种删除；回测前先看数据是否够用。点击周期进入**明细查询**（分页逐根看 OHLC、升降序、服务端全量导出 CSV）。
- 30S 为秒级周期：实时图表仅最近约 7 天，auto 模式同样走回放补深（实测可回放至 2025-01 之前）；`bars_all_tf.json` 快照行为不变（CLI/脚本继续用，其 30S 仍为实时 ~7 天窗口）。

## 重启 WEB 服务

工作台顶部的“重启 WEB 服务”在各导航页均可使用。确认后中止当前任务并清空内存中的回测、回放及监控信号表；已保存配置和文件保留，自动更新关闭，任务不会自动续跑。TradingView 不会关闭。

重启期间不接受新任务，重复点击只执行一次。页面等待新服务就绪后自动刷新并保留当前功能页。60 秒未恢复会显示手动启动命令，启动错误记录在项目目录 `.cache/service-restart.log`。首次安装此功能后，需要先按原方式重启一次服务以加载接口。仅支持 Windows。

## 启动 TradingView Desktop

点击“刷新图表”旁的“启动 TD”。服务在本机以 `--remote-debugging-port=9222` 启动 TD，就绪后自动刷新图表，不自动运行分析。仅支持 Windows。

TD 已运行但未开启调试时，页面先提示保存布局并确认重启；取消不会关闭 TD。启动中按钮禁用，其他页面共享启动状态。分析、回放或图表任务占用时请等待任务结束再试。

未安装、端口被其他程序占用或启动超时会显示具体错误。已连接但没有图表时，请在 TD 中打开图表再刷新。

## 首次分析

1. 启动带9222调试端口的TradingView Desktop并打开目标图表。当前行情分析必须退出Bar Replay历史回放。
2. 在工作台点击“刷新图表”，选择目标品种，填写起始日期，选择交易策略（当前：缠论V1）。
3. 展开“分析配置与支阻位预设”。选用WEB默认参数或已保存预设（可含各周期人工支阻位），设置每周期买卖点保留数量、近支阻阈值（绝对价差，默认10）与三个滑点（止损/兜底/保本，默认3/10/3）。
4. 点击“更新全部”。系统依次执行基础组件（画笔、画中枢、标记买卖点、支阻位）与所选策略的步骤（缠论V1：交易计划 → 标记进出场），流程按两组显示。
5. 点击流程中的模块，在“操作与结果”检查数量、K线截止时间与完整结果；在“规则说明”查看算法摘要和原始说明；在“依赖与示例”查看前置条件。

默认计算D/240/60/15/3五个周期。15分钟笔只保留最近30天，3分钟最近15天。可启用30秒数据以供3分钟状态的更低级别背驰判断；30秒笔不绘制。完整分析的支阻位预设暂不支持周线，周线仍可在独立支阻调参页使用。

## 执行依赖

完整流程的显示顺序用于操作导航，不等于每项都依赖前一项图形。

| 功能 | 必要前置 |
| --- | --- |
| 画笔 | 目标图表K线 |
| 画中枢 | 画笔（包含上级笔） |
| 标记买卖点 | 画笔、画中枢（类2/3/类3 依赖中枢；2买/2卖不依赖中枢） |
| 支阻位 | 画笔、选定WEB参数 |
| 交易计划 | 画笔，内部计算所需买卖点和中枢 |
| 进出场 | 画笔、支阻位、交易计划 |

前三行为**基础公用组件**（各策略共用），后三行为**交易策略 · 缠论V1** 的三步（支阻位 2026-09-29 起归属策略组）。

单项执行会重新运行必要前置。例如进出场执行画笔→支阻位→计划→进出场。未执行的模块标为“本轮未更新”；需要全部图形一致时使用“更新全部”。

## 手动与自动

默认手动。选择自动时立即运行完整流程，此后按设置间隔运行，默认5分钟，可设1至1440分钟。每轮结束后计算下一次运行时间，不积压重复任务。其他图表、回放或监控任务占用时等待。

调度位于WEB后端，关闭页面仍继续；服务重启后保留配置但关闭自动。修改配置下一轮生效。点击停止关闭自动，并在当前模块结束后停止后续步骤。单模块超过30分钟会终止并报告错误。

图表断开、品种改变、进入历史回放或模块失败，会停止后续步骤并关闭自动。处理原因后手动更新，或重新启用自动。

## 数据与结果

每轮使用独立缓存，固定目标图表、品种、日期和参数。画笔保留各周期输入K线快照，后续JS算法和WEB支阻位复用本轮输入。WEB支阻位直接使用本轮笔，不另建一套笔。

任务结果、输入和日志保存于 `.cache/analysis/runs/<任务ID>/`。请求的全部步骤成功后才发布至原 `.cursor/cache/`；发布前备份原文件到该轮的 `previous/`，写失败时回滚。页面显示任务版本和各步骤状态。

图表绘制本身不是事务：失败或停止可能留下部分已更新图形。此时页面不会报告整轮成功，应重新完整更新。历史验证数据标为无效，不能当成当前行情结果。

## 规则说明

各模块“规则说明”集中展示对应项目规则；“展开原始技能说明”读取当前仓库文档，而非另存一份全文。说明中有CLI用法和旧口径时，以模块标注区分。

进出场模块沿用JS技能算法；回测、回放和实时监控沿用现有Python引擎。两者尤其止损兜底、笔完成事件等口径不能混为一谈。支阻位改为使用WEB计算服务和预设，旧JS支阻技能说明仅供对照。

进出场规则分「进场」「出场」两大类呈现：进场链路（策略映射、三个公共条件、下沉链、策略专属条件、标记位置、成交与互斥）以「标记进出场」模块的规则卡为准——「交易计划」模块只负责给出各周期的策略状态，不构成进场信号；出场链路（止损位、保本位、顺势/逆势、结算）见同模块出场分区。工作台与回测/监控的逐项口径差异见模块末的附注卡与 `py_chain/SPEC.md` §2.1.5.2。

## 常见问题

- **最新走势没有笔**：先检查K线截止时间和任务错误；数据最新但反向走势未成笔时不会强行连接，末笔只按规则同向延伸。
- **自动更新等待**：查看占用者，停止或等待其他图表任务后继续。
- **历史回放拦截**：在TradingView退出Bar Replay，刷新目标图表后重新更新。
- **参数改了未生效**：支阻位在参数配置页保存预设后回工作台刷新并选用；其余模块（缠论核心/买卖点/进出场/交易计划）在参数配置页对应页签保存即可，下一轮任务自动读取。运行中的任务使用启动时参数快照。
- **某模块灰色**：本轮没有更新它，不能视为同轮有效结果；点击更新全部。

## 回测与监控独立入口

展开左侧“回测与监控”，选择全量回测、K线回放或 MT5实盘，每次仅显示对应功能。全量回测与K线回放切换时保留当前会话中的参数、筛选、日志和后台任务；**多策略并行（2026-10-02 起）**：全量回测按**策略分独立 TAB**（每策略一张卡：参数/进度/日志/批量进度表/保存按钮各自独立，来源=模块注册表 catalog，与工作台同一口径），**不同策略可同时启动、互不干扰**——信号行按行内策略归属各自 TAB，启动/清空表格/保存方案只作用于本策略，另一策略照常运行与展示；同一策略仍串行（重复启动被拒）。**回测为纯后台任务（2026-10-07 起）**：数据源固定本地存储、只读 SQLite 不连 CDP，不注册任务锁不占图表——回测运行中标记/删除标记、点行定位、支阻计算/画线、分析（含定时分析）、基础数据拉取、TD 启动、回放/实时启动均照常可用，反向（其他任务运行中启动回测）同样放行；回放/实时/基础数据/分析等**彼此之间**仍互斥。多品种批量在每策略 TAB 内照旧支持。**MT5实盘监控页**（不占用任务锁：进程在线状态、交易策略、持仓、已平仓盈亏汇总、订单与事件流，5秒刷新；多策略按 TAB 分离，每策略「开启/关闭交易」按钮写 live_state kv——停新开仓转 shadow、存量照常出场，webapp 重启不影响 live_trader 进程），策略选择与启动方式见 LIVE_GUIDE.md（live_config.json 的 strategy 键 / CLI --strategy）。子菜单提示回测/回放的运行或暂停状态（回测=任一策略运行即显示运行中）。回放/实时模式卡左上第一个参数为**交易策略**下拉（当前：缠论V1 / 强分型均线V1；与工作台、MT5 实盘同一注册表口径；回测卡无此下拉——TAB 即策略）。

全量回测卡片参数（每策略一张）：**预热提前/预热根数**、**结束日期**（空=到最新；含当日全天，限定历史区间回测——本地存储在加载层截断，未平仓浮动盈亏按结束日末根收盘结算；非法或早于起始日期会被拒绝启动）、**数据源（固定本地数据存储，2026-10-07 起）**与30秒级别开关：回测只读 SQLite（TV 关闭可跑），本地库缺该品种/周期会拒绝启动并列出缺项——先在「基础数据」页拉取入库。**支阻预设下拉已移除**（2026-09-29 二轮起）：回测支阻参数统一=「参数配置 → 支阻位」该品种当前生效方案（或品种自编辑参数），与工作台分析同一来源；历史方案快照中的旧 `sr_preset` 值仍可在重放时生效（后端优先级保留兼容）。叠加层开关只在参数配置支阻位页配置（方案的 srTypes）。手数/滑点/近支阻阈值/缠论核心阈值等算法参数统一在「参数配置」页分模块设置（2026-09-15 起回测卡片不再重复提供），启动时读取生效。回测与实盘同口径，回测结果可直接验证参数选择。

**多策略并行的隔离口径（2026-10-02）**：信号记录/盈亏汇总/资金曲线/品种页签均按当前策略 TAB 过滤（行内 strategy 字段归属；「清空表格」只清当前策略）；「保存方案」「全部保存」保存当前 TAB 策略的本轮新增行（方案 cfg 带策略 id，「载参数」自动切到该策略 TAB 回填）；「标记进出场/标记支阻位」在回测模式只画当前 TAB 策略的行；典型案例右击加入不受影响（三模式均可）。后端 `/api/backtest/start|pause|resume|stop` 带 `strategy` 路由到对应策略 Worker（缺省=缠论V1 兼容旧调用），`/api/status` 的 `backtests` 键给逐策略状态（`modes.backtest` 保留为聚合形状）。旧方案快照里的 `data_source=live/cache` 在重放时一律按本地存储执行（本地库缺数据会明确报错）。

信号列表、数量和盈亏汇总仅统计当前功能，可按 状态（单选）、策略、方向（多选下拉，不勾选=全部；方向按“方向”列展示口径，旧记录回退策略映射）过滤，三个筛选按功能各自记忆；“清空表格”仅删除当前功能记录。信号和支阻标记使用当前功能全部记录，不受表格筛选影响。绘制替换共享 TD 图表上的对应标记，删除标记仍作用于共享图表。

**标记的双周期显示（2026-09-13 起）**：「标记进出场」的进/出场箭头与「标记支阻位」的全宽横线，均以 `intervalsVisibilities` 在该行的**背驰级别 + 检测周期**两个周期同时可见（同一图形，不是画两份）；同类周期合并为连续区间时中间周期也会显示（如 3m+15m → 5m/10m 可见）。支阻横线改为全宽 `horizontal_line`（横贯全图、不限长度，锚=进场点K线），不再是从前左右各 5 根K线的限宽线段；横线按（背驰周期、近支阻价、检测周期）去重，同价同周期的重叠线只画一条。

点击信号记录行（键盘聚焦后可按 Enter 或空格）可定位到 TradingView 并**单行标记**：自动切换记录保存的品种与背驰周期，将信号K线居中（左右各约 50 根K线、自动适配价格范围），随后在同一图表会话内画出**该行**的进场箭头 + 出场箭头 + 近支阻全宽横线（颜色随工具条取色器，带全开周期可见性——切到 3/15/60/240/D 等任意周期均显示）。再次点击其它行会**替换**上一次的单行标记（图上始终只保留最近点击一行）；「标记进出场」「删除标记」也会一并清掉单行标记；被同向互斥过滤的信号不进信号列表（2026-10-01 起，旧行为=列表内标「同向过滤」）；历史保存方案明细里若仍有旧「同向过滤」行，则只定位不画标记；标记失败不影响定位结果（状态栏注明原因）。选中状态按记录 ID 保留，盈亏排序、状态筛选和数据更新不改变定位对象。表格上方显示定位进度及结果，历史加载最多等待 360 秒。运行或暂停中的任务、其他图表操作占用图表时不能定位。旧记录没有保存品种时需重新回测。后台提供 `POST /api/signals/locate`（`mode`、`id`、可选 `colors`）启动定位+标记、`GET /api/signals/locate` 查询最近任务，以及 `locate_done` 完成事件（`result.mark` 带标记结果）；前端同时查询状态以恢复丢失的完成事件。

独立入口支持 `/modes.html?mode=backtest`、`mode=replay`、`mode=live`（图表实时监控，已从主导航移出、直连仍可用），无效或缺省模式进入全量回测；MT5实盘只读页为 `/live`。

## 历史回测方案（保存 / 明细 / 对比）

仅全量回测模式（回放/实时不涉及）。把一次回测的**参数 + 本轮信号记录 + 汇总统计**一起留档，供跨方案对比调参效果。

- **保存方案**：全量回测卡片上的按钮，最近一次回测结束（完成或中途停止）且信号表有回测记录时可用。保存内容取该次运行的参数快照与**本轮新增**的信号行（按运行起点的行号过滤，连续多次回测不清空表格也不会串轮）；汇总额在保存时按表格盈亏汇总条同口径固化（已平仓胜率/盈亏比/已平仓盈亏/浮盈/合计/出场分布），明细与对比展示的就是这份固化值。方案名可重复保存时重名会被拒绝，不会覆盖。
- **存储**：基础数据库 `data/bars.db` 的 `bt_runs` / `bt_signals` 表。**清空表格**只清内存信号表，已保存方案不受影响；服务重启后照常可查。
- **历史方案面板**：选择「历史回测方案」页签。列表含保存时间、品种/周期/起始、已平仓、胜率、盈亏比、合计、信号数；操作有**明细**（在独立标签页打开，见下）、**载参数**（回填表单，不自动启动）、**重命名**、**删除**（二次确认，不影响当前表格）。
- **明细 = 独立页面**（2026-09-24 起，原弹窗已移除）：点列表「明细」以 `/bt-detail?id=<方案id>` 另开浏览器标签（同名标签复用并自动置前，不会越点越多），**控制台完全不被遮挡**——切模式、改参数、跑回测、操作信号表与历史方案面板均不受影响，两标签各操作各的。页面头部展示方案名、品种、周期、回测区间、保存时间与运行状态/耗时；关闭用页面右上「关闭」按钮或 Ctrl+W；换方案回控制台列表点对应「明细」即可（同标签导航到新方案）。
- **明细 · 概览**：默认显示六张指标卡（合计盈亏、已平仓盈亏、浮盈、胜率、盈亏比、已平仓笔数），下方为资金曲线、出场分布与亏损归因，底部可展开完整回测参数。所有金额和比例沿用保存方案的固化口径；出场分布的半平次数单独显示，曲线终点含浮盈。未做过归因的方案自动分析一次，也可在归因卡片设置「信号后 N 根」并点击「分析方案」重算；失败会在卡片内提示，可重试。
- **明细 · 交易记录**：切换页签后表格独占主要空间，固定表头和序号列，支持横向滚动；保留全部 17 列、分批出场分行、盈亏双向迷你条及整笔盈亏排序（降序 → 升序 → 原顺序）。点击行定位到 TradingView（单行标记带全开周期可见性，切到任意周期均显示），右键复制整笔交易信息；排序不改变原始序号。无信号、无出场记录或无亏损样本时显示对应提示。
- **明细 · 定位配置**：交易记录页签顶部有定位配置条——4 个标记颜色（做多/做空/出场/支阻，默认与控制台标记工具条一致）与「定位后保留K线」根数（默认 60）。该根数与控制台三张模式卡的同名输入框共用同一份设置并记住（localStorage，改任一处其余同步）；出场后实际K线不足 N 根时视口右缘显示到最新一根，回放态下再次定位会按新值向后扩窗重跳。图表被回测/监控任务占用时服务端返回 409，状态条提示"图表正被任务占用，请结束运行或暂停中的任务…"。
- **明细交互**：页签支持左右方向键与 Home/End；窗口缩放时资金曲线按新宽度重画。同方案分析刷新保留页签、排序、选中行、参数展开状态与滚动位置；分析/定位/加载的迟到响应按会话丢弃，不会覆盖新内容。窄屏自动调整指标与图表列数。
- **对比**：勾选两个及以上方案后点「对比选中」，展示指标×方案矩阵（盈亏类含浮盈/合计、出场分布、信号/未成交/持仓中/同向过滤计数）与参数对比表（与第一个选中方案不同的参数高亮）。
- 后台接口：`GET/POST/DELETE /api/bt/runs`（列表/删除）、`POST /api/bt/runs/save`（保存当前）、`GET /api/bt/runs/detail?id=`（明细）、`POST /api/bt/runs/rename`。

## 典型案例（典型交易留档）

全量回测的记录区第三个页签（仅全量回测显示，位于「历史回测方案」之后）。右击**进场信号记录**行或**历史方案明细页**交易记录行，菜单里选「复制并加入典型案例」：复制交易信息的同时把该行留档为一条案例（状态默认**待处理**）；「仅复制信息」则保持旧行为只复制。回放/实时模式下右击同样可加入（条目照常留档，切回全量回测查看）。

- **处理**：典型案例每行有滑动处理开关，点击切换**待处理 ⇄ 已处理**（已处理行弱化显示）；支持按状态过滤与刷新。点行或「定位」按钮走**行快照协议**定位到 TradingView 并画单行标记——不依赖内存信号表，清空表格/服务重启后仍可定位；「复制」回贴加入时留档的文本；「删除」二次确认后移除。
- **去重**：来源=当前信号按内容键（模式/品种/信号时间/检测周期/方向/策略）判同一行——确定性回测重跑的同一信号不重复入列（已在列表时提示）；来源=历史方案按方案 id + 行内序号判重。已处理条目再次右击不会自动重开，需先删除再加入。
- **存储**：基础数据库 `data/bars.db` 的 `bt_errors` 表（整行 JSON 快照 + 复制文本），不受清空表格与服务重启影响。
- 后台接口：`GET /api/bt/errors`（列表）、`POST /api/bt/errors`（加入，重复 → 409）、`POST /api/bt/errors/status`（待处理/已处理切换）、`DELETE /api/bt/errors?id=`（删除）。


## 近等双顶/双底参数简化（2026-10-02）

原「一小时近等端点补充确认」分支（15m 双动能确认）已整体删除，参数中心「画笔」页不再展示：近等双顶容差ATR（`nearDoubleAtrK`）、近等双顶价差比例（`nearDoublePct`）、60m双动能容差倍数（`nearDoubleLowerRelax`）、15m动能衰减比例（`nearDoubleLowerRatio`）。

现行为：容差只保留 `nearDoubleFixed`（近等双顶固定容差，品种报价单位绝对价差，默认 2.0）；比较「先影线后实体」——影线更极端直接后移，影线不满足比实体（bodyTop/bodyBottom）：后实体价不低于前实体直接后移，更低则差 ≤ 固定容差才后移；中间真实回调深度闸门同用该值。双底完全镜像。每周期开关 `nearDouble3/15/60/240/D`（默认全开）不变；画笔不再需要为 60m 预取完整 15m 历史。
