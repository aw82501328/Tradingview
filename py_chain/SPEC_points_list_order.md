# SPEC：买卖点列表顺序（2026-10-01 已实施）

> 状态：**已实施**。`findBuyPoints` / `findSellPoints` 返回值改为 **time 升序稳定排序**
>（Python `py_chain/chan_core.py` 与 JS `.cursor/skills/chan-core/scripts/chan_core.js` 同一提交同步改）。
> 本文件记录新契约、消费方语义与验证结论。时间一律 **UTC+8**。

## 新契约

- 识别逻辑不变（内部仍按 2/类2 → 1买/1卖 → 3/类3/4/类4 三段写入、同刻删类2保留离枢点），
  仅在两个函数 `return` 前统一 `sort(time)`。
- **稳定排序**：同刻多笔保持识别序（2/类2 前、1买/1卖 后、3/4类 最后），与
  `pickLatestFibPoint` 「同刻取数组靠后」口径一致。
- **尾点 = 时间最新的一笔**。三条识别 run 各自本就（弱）时间升序，排序等价于稳定归并。
- **每个周期一份独立列表**（买、卖又各一份）：15m 列表用 60m 上级笔，60m 用 240m，
  依 `UPPER_OF` 链；周期之间无顺序耦合。

## 消费方语义（改后）

| 消费方 | 语义 |
|---|---|
| `fx_ma` 引擎 `_fx_latest_points` | `buys[-1]`/`sells[-1]` = 该周期时间最新买/卖点。**回测（run）与实盘（live_trader step_to）同源同时生效；正在运行的实盘进程需重启加载。** |
| 交易计划 `trend_direction` / `trendDirection` | 自行 sort 后取末位，行为不变（同刻 tie 由稳定排序保持）。 |
| 交易计划 `predictPlan` 的 `matchAt` 首匹配 | **语义变化**：同一笔端点容差窗（±1 bar + ±max(0.2ATR, 0.05)）内多点并存时，由「分组优先（2类>1类>3类）」变为「时间最早」。同刻并列不变。 |
| 黄金分割 `pickLatestFibPoint` | 取 time 最大、同刻取靠后——稳定排序下逐笔口径不变。 |
| 画买卖点（锚定/近价合并/keepRecentAll） | 集合不变；仅同刻对恰好横跨 keep 截断边界时保留哪个可能翻转（视觉层）。 |
| `fxma_entry.js` / `chan_status.js` | 自行 sort / 2类块天然时间升，不变。 |

统一改时间序（Python+JS），而非只改单个消费方。
